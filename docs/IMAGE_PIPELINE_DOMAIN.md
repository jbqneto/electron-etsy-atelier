## What Was Ported

- orientation types: portrait, landscape and square source orientation
- crop suitability values: excellent, good, acceptable, aggressive and not_recommended
- image pipeline settings concepts: workflow preset, export structure, filename pattern, export largest only, bonus groups, JPG quality and upscale-before-crop flag
- portrait ratio groups: 2:3, 3:4, 4:5, 5:7, 11:14 and ISO
- landscape ratio groups: 3:2, 4:3, 5:4, 7:5, 14:11, ISO landscape and 16:9 Frame TV bonus
- inch-to-300-DPI export conversion
- ISO and Frame TV export sizes
- center-based automatic crop calculation
- crop coverage and suitability scoring
- default ratio selection logic
- artwork base-name normalization and printable output filename generation

## What Was Not Ported

- React components and UI state
- browser-only File, Image, canvas and Blob code
- JSZip packaging
- fetch calls and Next.js API route assumptions
- temporary upload/project logic
- manual crop editor behavior
- real Sharp processing
- Upscayl process execution

Those behaviors must be adapted later to the Electron architecture, where the main process owns filesystem, Sharp, external processes and OS integration.

## Persistent Image Cards

The Electron app persists scanned image cards per project at:

```txt
projects/<project-slug>/.atelier/image-cards.json
```

Cards are created from imported source artworks in `source-artworks/`. The main process reads dimensions, format, density and file size with Sharp, then uses the pure domain functions to derive source orientation, output orientation, ratio selections and active ratio group.

When rescanning, existing card IDs are preserved. Manual ratio selections, manual crop state, upscaled asset metadata and generated outputs are preserved unless image dimensions changed.

## Ratio Selection UI

The Project Detail image pipeline section lets the user review printable ratio groups per image card. The renderer only displays pure domain data and calls:

```txt
imagePipeline.updateImageCard(projectId, cardId, input)
```

Supported updates are intentionally narrow:

- `outputOrientation`: portrait or landscape
- `ratioSelections`: selected/unselected flags by ratio group key

The main process validates the input, loads `projects/<project-slug>/.atelier/image-cards.json`, recalculates ratios when orientation changes and writes the updated card back to the same metadata file. Orientation changes reset manual crops and generated outputs because those derived states would no longer be safe to reuse.

## Printable Ratio Generation

Printable JPG outputs are generated by the Electron main process only. The renderer calls:

```txt
imagePipeline.generatePrintableRatios(projectId)
```

The main process reads selected ratio groups from image cards, resolves project-local source files, applies manual crops when present or center auto-crops otherwise, resizes with Sharp and writes outputs to `printable-ratios/`. The first implementation generates only the largest size for each selected ratio group.

## Ratio Preset Model

Each ratio preset has:

- `key`: stable identifier such as `2x3` or `iso_landscape`
- `label`: display label such as `2:3`
- `ratio`: width divided by height
- `folderName`: deterministic output folder name
- `exports`: one or more output sizes in pixels
- `isFrameTvBonus`: optional flag for the 16:9 Frame TV group

The default print bundle includes common Etsy wall art ratios. Poster export filters out bonus/screen-only groups. Frame TV mode uses landscape 16:9 outputs.

## Crop Suitability

Auto crop uses the largest centered crop that matches the target ratio. Coverage is calculated as:

```txt
crop area / source image area
```

Suitability thresholds:

- `excellent`: coverage >= 90%
- `good`: coverage >= 80%
- `acceptable`: coverage >= 70%
- `aggressive`: coverage >= 60%
- `not_recommended`: coverage < 60%

By default, excellent, good and acceptable groups are selected. Aggressive and not recommended groups stay available for manual review in future UI work.

## Purity Boundary

This layer imports no Electron, Node filesystem, Sharp, React or browser APIs. It is safe to reuse from renderer UI for presentation and from main-process services for actual processing decisions.

There is no test runner configured yet. Expected examples for later tests:

- `detectSourceOrientation(1500, 1000)` returns `landscape`
- `detectSourceOrientation(1000, 1000)` returns `square`

- `normalizeArtworkBaseName("My Art 2x3.png")` returns `my_art`
